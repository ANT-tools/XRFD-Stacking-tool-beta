# Performance notes — XRD Image Toolkit 0.4.0

The main bottlenecks identified in 0.3.0 were not TIFF arithmetic itself. They
were repeated full-resolution display-percentile scans, re-running the entire
processing chain when only the display transform changed, repeated symmetry
interpolation for every quadrant, broad exact median filters, and recomputing
the registration reference FFT for every accumulation.

## CPU changes

- float32 working arrays for detector images and processed products
- staged cache: quantitative → enhancement → display
- sampled display percentiles
- viewer-only decimation for Matplotlib rendering
- reduced-grid approximation for broad Gaussian and median background models
- one interpolation into fiber coordinates for symmetry; quadrants are then
  generated by array flips
- sampled symmetry-correlation diagnostics
- cached reference FFT for registration
- real-valued FFTs (`rfft2` / `irfft2`) with SciPy worker threads
- configurable registration crop
- multi-worker TIFF decoding

Mean/sum stack accumulation retains a float64 accumulator before final float32
output.

## Optional GPU path

With CuPy installed, `auto` or `gpu` can move heavy filters, symmetry
resampling/averaging, registration FFTs, and median/sigma-clipped stack blocks
to an NVIDIA CUDA GPU.

GPU acceleration is intentionally optional because transferring data to and
from a GPU can be slower than CPU processing for small images or trivial
operations. The toolkit's fast CPU path remains the fallback.

## Representative CPU benchmark from the build environment

These timings are illustrative, not promises for another computer. Synthetic
2048 × 2048 float32 detector image:

| Operation | v0.3.0 | v0.4.0 optimized CPU |
|---|---:|---:|
| Display-only pipeline | ~0.27 s | ~0.09 s |
| Broad Gaussian background + high-pass | ~1.37 s | ~0.46 s with fast broad-background mode |
| Four-quadrant symmetry | ~3.20 s | ~1.12 s |
| Cached display-only change after heavy filtering | previously reran pipeline | ~0.02 s |

For a 1024 × 1024 image, an exact 41-pixel median background took roughly
22 s in the previous implementation in the same environment. The new
reduced-grid median-background approximation completed in roughly 0.2 s.
This is an approximation and can be disabled when an exact median is required.

A 3072 × 3072 CPU benchmark of the optimized package in the build environment
measured approximately:

- display-only: 0.2 s
- broad Gaussian background + high-pass: 1.1 s
- cached display change: 0.07 s
- four-quadrant symmetry: 2.7 s

Run `python benchmark_xrd_toolkit.py --size 2048` on the actual workstation to
measure the CPU and, when available, GPU paths on that hardware.
